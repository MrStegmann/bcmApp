# Implementation Plan: Caching the Play Match

**Branch**: `015-cache-play-match` | **Date**: 2026-10-25 | **Spec**: [specs/015-cache-play-match/spec.md](file:///j:/GitHub/BasketApp/bcmApp/specs/015-cache-play-match/spec.md)

**Input**: Feature specification from `specs/015-cache-play-match/spec.md`

## Summary

Implement a silent, non-blocking background caching system for the Play Match view using Expo SQLite with Drizzle ORM. As the scorekeeper records points, fouls, substitutions, and timer ticks, the in-progress state is debounced (800ms) and persisted to a `match_cache` SQLite table. If the app crashes, is suspended, or terminates unexpectedly, reopening the match automatically rehydrates the exact saved game state with the clock safely paused. When the match is concluded via "Save & Finish" (or explicitly discarded), the cached state is immediately purged to maintain storage hygiene and prevent state bleeding into future games.

## Technical Context

**Language/Version**: TypeScript ~6.0.3, Strict Mode enabled (`noImplicitAny`, `strictNullChecks`).  
**Primary Dependencies**: React 19.2.3, React Native 0.86.3, Expo SDK ~57.0.25, Zustand ^5.0.8, Drizzle ORM ^0.45.3, `expo-sqlite` ~57.0.3, NativeWind ^4.2.1.  
**Storage**: Local relational SQLite (`bcmapp.db`) managed via `drizzle-orm/expo-sqlite`, `match_cache` table with WAL mode and foreign key cascading.  
**Testing**: Jest ^29.7.0 with `@testing-library/react-native`.  
**Target Platform**: Mobile (iOS & Android via Expo).  
**Project Type**: Mobile Application (React Native / Expo).  
**Performance Goals**: Silent background persistence debounced at 800ms; zero UI thread stutter (60 fps); rehydration time < 500ms (budget < 1.0s); zero loading overlays or modal spinners during play.  
**Constraints**: Completely silent operation; graceful fallback on corrupted/outdated cache; automatic purge on match finalization ("Finalizar" / Save & Finish) and on session discard/cancellation.  
**Scale/Scope**: Single active match cached at a time (or per-match cache records), snapshot payloads ~10-50 KB of JSON.
