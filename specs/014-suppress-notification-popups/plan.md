# Implementation Plan: Suppress Notification Popups

**Branch**: `014-suppress-notification-popups` | **Date**: 2026-10-25 | **Spec**: [specs/014-suppress-notification-popups/spec.md](file:///J:/GitHub/BasketApp/bcmApp/specs/014-suppress-notification-popups/spec.md)

**Input**: Feature specification from `/specs/014-suppress-notification-popups/spec.md`

## Summary

Prevent visual heads-up notification popups from disrupting users while using the application, especially during live basketball matches, while preserving all incoming notifications in a local in-app notification center. The implementation delivers an adaptive notification suppression evaluator, dynamic AppState and match-mode lifecycle tracking, Drizzle ORM SQLite persistence for notification history and settings, and a dedicated in-app notification center and settings modal in `src/features/notifications/`.

## Technical Context

**Language/Version**: TypeScript ~6.0.3, React 19.2.3, React Native 0.86.3, Expo ~57.0.25  
**Primary Dependencies**: Zustand (^5.0.8), Drizzle ORM (^0.45.3), expo-sqlite (~57.0.3), NativeWind (^4.2.1), React Native AppState API  
**Storage**: SQLite via `expo-sqlite` managed with `drizzle-orm` (tables: `notifications`, `notification_settings`)  
**Testing**: Jest (^29.7.0) with `@testing-library/react-native` (TDD first)  
**Target Platform**: iOS and Android mobile platforms via Expo managed workflow  
**Project Type**: Mobile Application  
**Performance Goals**: < 16ms frame budget (60 fps), < 50ms suppression state transition latency, 0% message loss  
**Constraints**: Fully offline-capable, zero visual popups during live matches, strict adherence to Constitution Principles I-VI  
**Scale/Scope**: 1 new feature module (`src/features/notifications/`), 2 SQLite tables, 3 UI modal/button components, ~15-20 test suites/cases
